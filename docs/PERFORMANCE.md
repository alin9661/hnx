# Performance contract

The rewrite targets the bottlenecks users can perceive:

| Scenario | Budget | Why it matters |
| --- | ---: | --- |
| Warm cached command | p50 <= 100 ms | Shell use should feel immediate. |
| Cold top feed | p50 <= 750 ms | Replaces serial per-story fetches. |
| Firebase fallback | >= 6x serial baseline | Bounded fan-out must remain worthwhile. |
| TUI key-to-frame, 10k-comment thread | p95 < 16 ms | Navigation should remain at 60 Hz. |
| Release binary | < 15 MiB | Easy installation and fast startup. |
| Idle resident memory | < 30 MiB | Appropriate for a terminal utility. |

The main expected gain comes from request topology. The historical client
fetched feed IDs and then requested each item serially. `hnx` uses Algolia's
batched indexes for records, reconciles them against canonical Firebase IDs,
and fetches only missing Firebase items with a semaphore capped at 12 while
restoring canonical order.

Development-machine baseline observations (Apple Silicon, wired broadband,
August 2026) were:

| Operation | Observed wall time | Relative to serial feed |
| --- | ---: | ---: |
| Legacy-shaped 30-item serial Firebase feed | 3.48 s | 1.0x |
| 30 Firebase items, concurrency 12 | 0.409 s | 8.5x faster |
| One Algolia front-page batch | 0.284 s | 12.3x faster |
| Algolia 418-node thread payload | 0.495 s | n/a |

These measurements isolate request shape; the production Top feed performs
canonical reconciliation and therefore is not identical to the one-request
Algolia row. Warm cache and key-to-frame results are generated by the commands
below and should be recorded per release.

The first integrated release-mode run on the same machine produced:

| Production path | Result |
| --- | ---: |
| Hybrid Top, 30 items, five fresh-cache samples | 0.32 s median (0.30–0.67 s) |
| Warm offline Top JSON, 100 sequential processes | 4.9 ms mean per process |
| 10k-comment navigation + 120x40 two-panel frame | 181.8 µs median; 201.7 µs sample p95 |
| Stripped release binary | 9.06 MB |
| `hnx --version` peak RSS | 7.8 MB |

Network timings are environment-sensitive. The render result comes from 100
Criterion samples; its raw sample data is written below `target/criterion/`.

Run microbenchmarks with:

```bash
cargo bench
```

The `key_to_frame_10k_comments_120x40` benchmark preloads 10,000 comments,
moves the selection near the end of the thread, and measures one navigation
event plus one complete Ratatui TestBackend frame. This intentionally excludes
thread construction so the result tracks steady-state interaction latency.

Measure end-to-end commands using a warm and cold cache separately. Network
results must report region, connection type, sample count, p50, and p95; a
single favorable observation is not a benchmark.
