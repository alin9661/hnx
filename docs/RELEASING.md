# Releasing

Release automation is generated by cargo-dist 0.32.0 from
`dist-workspace.toml`. Pull requests run `dist plan`; a SemVer tag builds
checksummed archives, shell and PowerShell installers, a CycloneDX SBOM,
auditable binaries, and GitHub artifact attestations.

The CI workflow is intentionally marked `allow-dirty = ["ci"]`. cargo-dist
0.32.0 generates the CycloneDX upload reference with the singular
`steps.cargo-cyclonedx.output.paths`; the checked-in workflow corrects that to
GitHub Actions' `steps.cargo-cyclonedx.outputs.paths`. Keep this correction when
regenerating CI until cargo-dist fixes its generator.

Before tagging:

```bash
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-targets
dist generate --check
dist plan
```

Then update `VERSION` and `CHANGELOG.md`. Map four-part `VERSION` value
`A.B.C.D` to version `A.B.C` in `Cargo.toml` and `Cargo.lock`. Use the four-part
value in PR titles and changelog headings, but create the cargo-dist release tag
as `vA.B.C`; cargo-dist parses announcement tags as three-part SemVer. Commit,
tag, and push that mapped tag. The crate is published separately with
`cargo publish` after the GitHub artifacts pass smoke tests.

Homebrew publication requires an initialized `homebrew-tap` repository and a
`HOMEBREW_TAP_TOKEN`; enable cargo-dist's `homebrew` installer only after those
external resources exist. The Scoop template under `packaging/scoop` is filled
with the release archive URL and hash when a separately authorized bucket
publication workflow exists; this repository does not create or mutate that
external resource.
